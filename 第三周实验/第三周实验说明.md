# 第三周实验说明：部署本地 7B 模型并提供 API 与 Web 交互

## 这周在做什么实验

本周把一个真实的 7B 级开源指令模型部署在本机：下载并校验 Qwen2.5-7B-Instruct-GGUF 的 Q4_K_M 量化权重，用 `llama-cpp-python` 完成一次推理，再把同一模型接入终端多轮对话、本地 HTTP API 和浏览器页面。核心目标是理解模型文件、推理引擎、CPU/GPU 资源分配和应用入口之间的关系。本周只做推理与应用配置，不训练或修改模型权重。

## 实验一：准备并校验量化模型

指导书面向 Windows、PowerShell、NVIDIA CUDA 和第一周建立的 `llm-course` Conda 环境。第三周新增 `llama-cpp-python[server]==0.3.34`，并要求确认安装版本支持 GPU offload。`classroom/tools/download_official_model.py` 从固定版本下载两片官方 GGUF 权重；`classroom/step01_check_model.py` 对照清单检查文件大小与 SHA-256，避免把未下载完整的分片当成模型。

**当前材料状态：**项目目录没有 `models/` 和 `download_manifest.json`。下载脚本只获取两个 GGUF 分片，不生成清单；`step01_check_model.py` 在缺少清单时会报错。执行该校验前，需要先取得课程提供的对应版本清单。指导书展示的校验通过结果不能视为当前目录已完成校验。

Q4_K_M 量化把权重存储压缩到约 4.36 GiB，但模型仍有约 7.62B 参数。量化降低的是权重存储精度与文件体积，并不把 7B 模型变成更小层数的网络。两个分片属于同一个模型，后续加载时指定第一片即可。

## 实验二：完成一次本地推理

`step02_local_inference.py` 用 `llama_cpp.Llama` 加载模型，设置 `n_ctx=2048`、`n_gpu_layers=16`、`n_threads=8` 和 Qwen 使用的 `chatml` 对话模板。部分层放到 GPU，其余层由 CPU 和系统内存处理，以适应指导书中的 4 GB 显存设备。脚本记录加载前后的可用内存、显存、加载时间、生成时间、token 数和速度，然后让模型回答一个关于量化与混合推理的问题。

验收重点是：两个分片已通过校验，终端打印真实的 `user` 与 `assistant` 文本，`outputs/step02_local_inference.json` 保存请求和资源统计，最后出现 `checkpoint: PASS`。指导书中的秒数与显存数值是指定机器上的示例，不应当作为其他设备必须达到的固定值。

## 实验三：从单轮推理到终端多轮对话

`step03_interactive_chat.py` 在程序启动时加载一次模型，并维护一个 `messages` 列表。每轮都把 system 消息、此前的 user/assistant 消息和本轮问题一起发送给模型，因此它能在当前会话中引用前文。`--demo` 自动运行两轮演示；无参数时从终端持续读取输入，输入 `exit` 或 `quit` 结束。历史保存在该进程内存中，程序退出后不会自动长期保存。

## 实验四：开放本地 API 并复用同一模型

`start_local_api.ps1` 调用 `server_launcher.py` 启动 `llama_cpp.server`，在 `127.0.0.1:18080` 暴露 OpenAI 兼容接口。`step04_api_client.py` 先通过 `GET /v1/models` 检查服务，再向 `POST /v1/chat/completions` 发送 JSON 消息，并把请求与响应写入 `outputs/step04_api_response.json`。模型推理发生在服务器进程，客户端只负责构造请求和读取结果。

`step05_application_scenarios.py` 通过同一个 API 调用同一套权重，分别展示编程助手、学习伴侣和游戏 NPC。三个场景主要改变 system 提示词、用户问题和生成温度；它们是三种应用配置，不是三个重新训练的模型。结果保存为 `outputs/step05_application_scenarios.json`。

## 实验五：提供浏览器页面

`step06_web_interface.py` 在 `127.0.0.1:18081` 启动轻量 Web 服务。浏览器打开页面后，通过 `/api/status` 检查模型 API，通过 `/api/chat` 把消息转发到 18080 端口的模型服务。Web 服务本身不加载第二份 7B 权重；一次浏览器请求的记录保存为 `outputs/step06_web_response.json`。页面中的对话历史只在当前浏览器页面内，刷新后清空。

## 建议运行顺序与验收材料

在 Windows PowerShell 中进入 `第三周实验`，激活 `llm-course` 并按指导书安装 CUDA 版依赖后，先取得与固定版本匹配的 `models/Qwen2.5-7B-Instruct-GGUF/download_manifest.json`，再依次执行：

```powershell
python -s .\classroom\tools\download_official_model.py
python -s .\classroom\step01_check_model.py
python -s .\classroom\step02_local_inference.py
python -s .\classroom\step03_interactive_chat.py --demo
```

完成终端实验并退出对话程序后，在第一个终端启动 API；保持该终端运行，在第二个终端执行客户端、应用场景和 Web 服务：

```powershell
.\classroom\start_local_api.ps1
```

```powershell
python -s .\classroom\step04_api_client.py
python -s .\classroom\step05_application_scenarios.py
python -s .\classroom\step06_web_interface.py
```

核对 `checkpoint: PASS`、`outputs/` 中的 JSON、API 响应和浏览器实际回答。上面两段命令属于不同终端；Web 服务持续运行时，按 `Ctrl+C` 停止。

## 一句话总结

第三周实验把量化模型文件接入本地推理引擎，再通过终端、API 和 Web 页面逐层开放同一个模型的能力，同时观察小显存设备上的 CPU/GPU 混合推理。
