# 第六周实验说明：验证 LoRA 适配器并清洗微调数据

## 这周在做什么实验

本周承接第五周的数据生成，完成两项准备工作：在 Qwen2.5-0.5B-Instruct 上挂载 LoRA 适配器，验证保存与重载过程；清洗学习伴侣 JSONL，并划分训练集和验证集。LoRA 演示脚本只检查适配器能否正确工作，没有执行反向传播或参数更新。真正的 LoRA 训练安排在第七周。

## 实验一：准备可用于 PEFT 的基座模型

第三周使用的 7B GGUF 文件是面向 `llama.cpp` 的量化推理文件；第六周改用 Hugging Face Transformers 格式的官方 `Qwen/Qwen2.5-0.5B-Instruct`，以便 PEFT 在指定线性层挂载适配器。`classroom/download_official_model.py` 下载固定版本的配置、分词器和 `model.safetensors`，并可用 `--verify-only` 核对权重大小与 SHA-256。指导书的目标环境是带 NVIDIA CUDA 的 `llm-course`，本周新增 `peft`、`accelerate` 和 `psutil`。

## 实验二：挂载并验证 LoRA

LoRA 冻结基座权重 `W`，在目标线性层旁加入可训练的低秩矩阵 `A`、`B`，近似表示增量：`W' = W + (α/r)BA`。默认配置为 `r=8`、`α=16`、`dropout=0.05`，只挂在每层注意力的 `q_proj` 与 `v_proj` 上。

`classroom/lora_lab.py` 检查可训练参数比例、挂载模块数和前向 logits 形状；随后保存适配器、重新加载基座与适配器，比较加载前后的输出，并生成一条固定文本。指导书示例中，可训练参数为 540,672 个，约占 0.1094%，挂载位置为 48 组。初始 LoRA 的 B 矩阵为零，所以此时保存/重载后的输出应与未训练状态一致。这个结果证明序列化和加载链路正常，不是微调效果。

`--r 4|8|16` 可观察秩与可训练参数量的关系；`--targets qv|qkvo|all` 可观察挂载范围的影响；`--method dora` 是扩展对照。增大秩或挂载范围通常增加可训练参数，但本周脚本仍不训练它们。

## 实验三：清洗第五周数据

`classroom/prepare_dataset.py` 先做规则清洗：逐行解析 JSONL，检查 `instruction`、`input`、`output`、`task_type`、`difficulty` 等字段，拒绝空指令/回答、非法枚举与未闭合代码围栏；然后分别比较问题和回答的字符 4-gram，覆盖率达到 `0.95` 时剔除近乎重复的记录。

完整流程还需给每条记录计算困惑度 `PPL = exp(平均交叉熵)`，使用本地 0.5B 模型排查极端噪声；阈值为 1000。困惑度反映模型预测文本的难易程度，不能当作事实正确性分数。清洗后按固定种子 `202606` 随机划分，默认验证集占 10%，输出 `data/cleaned.jsonl`、`data/train.jsonl`、`data/validation.jsonl` 和报告。

**当前材料状态：**指导书提到的 `student_materials/prepare_dataset.py` 未出现在本项目目录。现有 `classroom/prepare_dataset.py` 的 `calculate_perplexities()` 仍是 `NotImplementedError`；因此在提供第五周源数据后，可以先用 `--no-quality` 完成规则清洗与划分，默认开启的完整困惑度清洗必须先实现该函数。脚本默认源文件名是 `course_learning_500_flash_think.jsonl`，也可通过 `--source` 指向自己第五周实际生成的 JSONL。

## 建议运行顺序与验收材料

在 `第六周实验` 目录、已配置的 `llm-course` 环境中执行：

```text
python -s classroom/download_official_model.py
python -s classroom/download_official_model.py --verify-only
python -s classroom/check_environment.py
python -s classroom/lora_lab.py
python -s classroom/prepare_dataset.py --source ../第五周实验/data/course_learning_500.jsonl --no-quality
```

最后一行的文件名应换成实际生成的数据文件。完成困惑度函数后，再移除 `--no-quality` 运行完整清洗，并检查报告中 `passed`、拒绝原因、样本数量和训练/验证 ID 是否无交集。指导书中“500 条原始记录 → 剔除 2 条 → 448 条训练、50 条验证”是示例输入下的结果；使用自己的数据时，数量可能不同。若第五周数据尚未准备，清洗脚本会报告 `SKIPPED`，不能把它当作清洗通过。

## 与后续实验的关系

第七周需要这里保存的 0.5B 基座模型，以及完整清洗后生成的 `train.jsonl`、`validation.jsonl`。本周保存的 LoRA 演示适配器没有经过训练，不应拿它代替第七周的微调结果。

## 一句话总结

第六周先证明“冻结基座、挂载和重载小适配器”这条技术链路可用，再把生成数据整理成可供下一周训练与评估的两份数据集。
