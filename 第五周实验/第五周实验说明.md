# 第五周实验说明：用 Prompt Skill 和模型 API 生成指令微调数据

## 这周在做什么实验

本周为“《大模型原理与应用》课程学习伴侣”准备监督微调数据。实验先设计可复用的 Prompt 和 Skill，再通过兼容 Chat Completions 的模型 API 批量生成至少 500 条指令—回答记录，校验格式、去重并保存为 JSONL。这里是在**制备训练数据**；本周没有更新本地模型参数。

## 实验一：认识 SFT 数据格式

一次 API 请求使用 `messages` 列表，通常把 Skill 与生成规则放进 `system.content`，把本批任务放进 `user.content`。模型返回的 `assistant.content` 再被解析为数据记录。`messages` 是请求协议，训练文件采用另一种结构：每行一条 JSON 对象，核心字段为 `instruction`、`input`、`output`，另有 `task_type`、`difficulty`、`id` 和生成来源信息。

`instruction` 是学生问题或任务；`input` 是可为空的补充上下文；`output` 是学习伴侣的参考回答。`task_type` 限定在基础与部署、数据与微调、优化与评估、从模型到智能体四个课程方向；`difficulty` 使用 `beginner`、`intermediate`、`advanced`。JSONL 适合逐批追加与续传，脚本还会同步生成易于人工阅读的 JSON 数组。

## 实验二：设计 Prompt 与 Skill

`classroom/prompt_template.txt` 规定每批数量、总目标、四类课程主题、字段、难度和 JSON 输出要求。批次号与数量由脚本填入，因此同一模板可以重复用于多次请求。

`classroom/skills/course_learning_companion/SKILL.md` 定义长期复用的“学习伴侣”行为：根据学生水平解释概念，对错误回答指出错因，给出适量引导问题，并要求事实可核查。Prompt 负责“本批要生成什么”，Skill 负责“这一类回答应怎样写”。指导书还安排查看外部 `find-skills` 和 `tdd` Skill，目的是认识 Skill 的搜索与多文件组织方式；它们不注入本实验的学习伴侣数据生成请求。

## 实验三：调用 API 批量生成

`classroom/generate_sft_data.py` 从环境变量读取 `COMMERCIAL_API_URL`、`COMMERCIAL_API_KEY`、`COMMERCIAL_API_MODEL`，可通过 `COMMERCIAL_API_EXTRA_JSON` 传入服务商参数。脚本把单个指定 Skill 的文本放入 system 消息，把填好的模板放入 user 消息，调用 API 后解析返回的 JSON，拒绝空的指令或回答、非法类别和难度，以及重复的 `instruction`/`input` 组合。有效记录按批次写入 JSONL；失败批次的原始响应写到 `outputs/failed_responses/` 供检查。

`--count` 是最终目标总量，`--batch-size` 是每次请求的条数，默认 10。`--resume` 从已有 JSONL 的条数继续补足目标，而不是再增加 `--count` 条。`--dry-run` 仅展示组合后的 system/user 文本，不读取 API 密钥，也不发送请求。脚本还保存生成清单，记录模型、Skill 版本与哈希、Prompt 哈希、条数、调用次数和耗时；每条数据的 `generation` 字段记录模型、批次和时间。

## 建议运行顺序与验收材料

先在 `第五周实验` 目录运行不联网的模板检查：

```text
python -s classroom/generate_sft_data.py --count 10 --skill course_learning_companion --dry-run
```

随后按所选服务的控制台信息设置上述三个必需环境变量，先生成 10 条并人工检查，再生成 500 条。下面的输出路径只是示例，实际模型名称由环境变量决定：

```text
python -s classroom/generate_sft_data.py --count 10 --skill course_learning_companion --output data/course_learning_10.jsonl
python -s classroom/generate_sft_data.py --count 500 --skill course_learning_companion --output data/course_learning_500.jsonl
python -s classroom/generate_sft_data.py --count 500 --skill course_learning_companion --resume --output data/course_learning_500.jsonl
```

验收时检查 JSONL 条数达到 500、每行可独立解析、字段齐全、类别与难度合法，并抽样核对知识正确性、教学风格和重复内容。脚本的结构校验不能代替人工审阅，也不能保证 500 条回答都事实正确。`checkpoint: PASS` 表示脚本达到了指定数量并完成保存，不表示每条数据已通过人工质量审核。

## 与后续实验的关系

第六周会对这里产生的 JSONL 做规则与模型级清洗，再划分训练集和验证集；第七周才使用清洗后的数据对本地模型做 LoRA 微调。当前项目目录只包含生成脚本和模板，尚未包含生成好的 `data/` 文件，因此文档中的 500 条属于实验目标，不是当前目录已有的结果。

## 一句话总结

第五周实验用 Prompt 定义批量任务、用 Skill 约束学习伴侣的回答方式，再用模型 API 产出可追踪、可续传、可供后续清洗和微调的指令数据。
